## 1. Ajan Sağlık Kontrolü ve Windows Ortamı Log Analizi

"Dashboard üzerinde ajanların sağlık durumunun ve sistem loglarının izlenmesi" görevi doğrultusunda, Wazuh SIEM mimarisine bağlı olan Windows ve Ubuntu (WSL) ajanlarının bağlantı ve sağlık durumları kontrol edildi. 

İlk aşamada, Windows 11 ortamındaki ajanın merkeze ilettiği başlangıç güvenlik yapılandırma taramaları (**SCA - CIS Benchmarks**) ve kimlik doğrulama (*Windows logon success*) logları Wazuh Dashboard üzerindeki **Threat Hunting** (Tehdit Avı) arayüzünden izlendi. Sistemin ürettiği ham logların, Wazuh Manager tarafından analiz edilerek Seviye 3 (Level 3) ve üzeri önceliğe sahip güvenlik alarmlarına dönüştürülmesi süreci uygulamalı olarak gözlemlendi.

## 2. Linux (WSL) Ortamında Saldırı Simülasyonu

Linux (Ubuntu) tabanlı işletim sistemlerinin yapısı gereği olağan durumlarda kısıtlı log üretmesi sebebiyle, WSL ajanı üzerinden log yakalama kapasitesini doğrulamak adına kontrollü bir siber saldırı simülasyonu gerçekleştirildi. 

İşleme başlamadan önce, WSL ortamında varsayılan olarak inaktif olan loglama servisi (`rsyslog`) manuel komutlarla ayağa kaldırıldı. Ardından **MITRE ATT&CK** çerçevesine uygun şekilde aşağıdaki eylemler simüle edildi:

* Yetki yükseltme ve kaba kuvvet denemesi (yanlış parola ile `sudo su`)
* Sistemde kalıcılık sağlama (yeni kullanıcı ekleme)
* Savunmadan kaçınma ve iz silme (eklenen kullanıcıyı silme)

Üretilen `"PAM: User authentication failed"` ve `"New user added/deleted"` alarmlarının merkez sunucuya başarılı bir şekilde düştüğü teyit edilerek izleme görevi tamamlandı.

## 3. Sistem Sağlığının Korunması (Teardown Prosedürü)

Günlük tehdit avı ve log analizi süreçlerinin tamamlanmasının ardından, veri tabanında (index) oluşabilecek yapısal bozulmaların önüne geçmek adına laboratuvar ortamının güvenli kapatılma (teardown) prosedürleri uygulandı.

# Daily Operations Report: SIEM Log Analysis and Endpoint (Agent) Configuration

**Date:** July 21, 2026  

---

## 1. Agent Health Check and Windows Environment Log Analysis

In accordance with the task of "monitoring the health status of agents and system logs on the Dashboard," the connection and health status of the Windows and Ubuntu (WSL) agents connected to the Wazuh SIEM architecture were checked. 

In the first phase, the initial security configuration assessment (**SCA - CIS Benchmarks**) and authentication (*Windows logon success*) logs transmitted to the center by the agent in the Windows 11 environment were monitored via the **Threat Hunting** interface on the Wazuh Dashboard. The process of raw logs generated by the system being analyzed by the Wazuh Manager and converted into security alerts with a priority of Level 3 and above was practically observed.

## 2. Attack Simulation in the Linux (WSL) Environment

Since Linux (Ubuntu)-based operating systems produce limited logs under normal circumstances by design, a controlled cyber attack simulation was conducted to verify the log capture capacity via the WSL agent. 

Before starting the operation, the logging service (`rsyslog`), which is inactive by default in the WSL environment, was started using manual commands. Subsequently, the following actions were simulated in accordance with the **MITRE ATT&CK** framework:

* Privilege escalation and brute-force attempt (using `sudo su` with an incorrect password)
* Establishing persistence in the system (adding a new user)
* Defense evasion and clearing tracks (deleting the added user)

The monitoring task was successfully completed by verifying that the generated `"PAM: User authentication failed"` and `"New user added/deleted"` alerts were successfully received by the central server.

## 3. Maintaining System Health (Teardown Procedure)

Following the completion of the daily threat hunting and log analysis processes, safe shutdown (teardown) procedures for the laboratory environment were implemented to prevent structural corruption that could occur in the database (index). 

The Ubuntu agent (`wazuh-agent`) and `rsyslog` service running in the background of the operating systems, along with the Windows agent services (`WazuhSvc`), were stopped via manual commands using the terminal and PowerShell.
